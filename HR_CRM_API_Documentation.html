🔐 Authentication & Setup

Authorization Header

All protected endpoints require:


Authorization: Bearer <your-jwt-token>

Content-Type

For JSON requests use:
Content-Type: application/json

For file uploads use:
Content-Type: multipart/form-data

Error Format

All errors return:


{ "message": "Error description" }

Permissions

Role-based. If your role doesn't have the required permission, you'll receive 403 Forbidden.

Payroll Module

Manages the full salary lifecycle from configuration to payment. Includes allowances, deductions, bonuses, and payslips.

/api/payroll

Payroll Workflow

1. Set Salary Config
→
2. Generate (Draft)
→
3. Add Allowances / Deductions
→
4. Approve
→
5. Mark as Paid
Salary Configuration
POST /api/payroll/salary-config PAYROLL_CREATE Set Salary Config

HR sets the base salary for an employee once. After this, payroll auto-generates on the 1st of every month.

Request Body

{
  "userId": 5,
  "userName": "John Doe",
  "basicSalary": 50000.00
}

Response 200

{
  "message": "Salary configuration saved...",
  "config": {
    "userId": 5,
    "userName": "John Doe",
    "basicSalary": 50000.00
  }
}
GET /api/payroll/salary-config/{userId} PAYROLL_VIEW Get Salary Config

Get the saved salary configuration for a specific employee.

Response 200

{
  "userId": 5,
  "userName": "John Doe",
  "basicSalary": 50000.00
}
GET /api/payroll/salary-config/all PAYROLL_VIEW All Salary Configs

Get salary configuration for all employees.

Response 200

[
  { "userId": 5, "userName": "John Doe", "basicSalary": 50000.00 },
  { "userId": 6, "userName": "Jane Smith", "basicSalary": 60000.00 }
]

Manually generate a payroll record for one employee. Status is set to Draft. System auto-calculates attendance, tax deductions, and overtime.

  "userName": "John Doe",
  "basicSalary": 50000.00
}

  "payrollId": 12,
  "userId": 5,

  "month": "2026-03-01T00:00:00",
  "year": 2026,
  "basicSalary": 50000.00,
  "overtimePay": 0.00,
  "bonusAmount": 0.00,
  "totalAllowances": 0.00,
  "absentDeduction": 0.00,
  "taxDeduction": 5000.00,
  "totalDeductions": 0.00,
  "workingDays": 26,
  "presentDays": 24,
  "absentDays": 2,
  "netSalary": 45000.00,
  "status": "Draft",
  "createdDate": "2026-03-17T10:00:00",

  "approvedDate": null

POST /api/payroll/auto-generate PAYROLL_GENERATE Auto-Generate All

Trigger payroll generation for ALL employees who have a salary configuration. Skips employees who already have a payroll for the current month.

Response 200

{
  "message": "Auto payroll generation completed.",
  "generated": 10,
  "skipped": 2
}
GET /api/payroll/all PAYROLL_VIEW All Payroll Records

Get all payroll records across all employees and months.

Response 200 — Array of payroll objects (same shape as generate response)

GET /api/payroll/{userId} PAYROLL_VIEW Payroll By Employee

Get all payroll records for a specific employee across all months.

Response 200 — Array of payroll objects for that user

PUT /api/payroll/{payrollId} PAYROLL_UPDATE Update Draft Payroll

Update a payroll record. Only works on payrolls with status = Draft. Approved or Paid payrolls cannot be edited.

Request Body

{
  "userId": 5,
  "userName": "John Doe",
  "basicSalary": 52000.00
}

Error 400

{
  "message": "Payroll not found or cannot
be edited. Only Draft payrolls
can be updated."
}
DELETE /api/payroll/{payrollId} PAYROLL_DELETE Delete Payroll

Permanently delete a payroll record.

Response 200

{ "message": "Payroll deleted successfully." }

Attendance Module

Tracks employee check-in/out, GPS location, live tracking, movement trails, and total working hours.

/api/attendence
ℹ️
Security Rule: Employees can only check-in/check-out for themselves. The token's userId must match the request userId. HR/Managers can view all employees' data including live locations and trails.
⚡
Real-Time (SignalR): When an employee calls PUT /location, the new GPS coordinates are instantly broadcast to all HR managers connected via the LocationHub WebSocket. HR dashboard should subscribe to the EmployeeLocationUpdated event.
Check-In / Check-Out
POST /api/attendence/checkin Employee Check-In

Record employee check-in with optional GPS coordinates. System also captures IP address and device/browser info automatically.

Request Body

{
  "userId": 5,
  "latitude": 12.9716,
  "longitude": 77.5946
}

Response 200

{
  "message": "Check-in successful",
  "userId": 5,
  "checkInTime": "2026-03-17T09:00:00",
  "ipAddress": "192.168.1.10",
  "deviceInfo": "Chrome/Windows",
  "checkInLatitude": 12.9716,
  "checkInLongitude": 77.5946
}
POST /api/attendence/check-out?userId=5 Employee Check-Out

Record employee check-out. Pass userId as a query parameter.

Response 200

{
  "message": "Check-out successful",
  "userId": 5,
  "time": "2026-03-17T17:30:00"
}
Working Hours & History
GET /api/attendence/total-hours?userId=5 Total Hours Per Day

Get daily working hours summary. HR can view any employee; employees can only view their own.

Response 200

{
  "userId": 5,
  "totalHoursHistory": [
    { "date": "2026-03-17", "totalHours": 8.5 },
    { "date": "2026-03-16", "totalHours": 9.0 }
  ]
}
GET /api/attendence/history/{userId} Attendance History

Get full attendance session log for an employee. Each row = one check-in/checkout session. HR can view all; employees can only view own.

Response 200 — Array of session records with check-in/out times, location, IP, device, status

Onboarding Invite Module

HR generates a secure one-time invite link for a new employee to self-fill their onboarding form.

/api/onboardinginvite

Onboarding Invite Flow

1. HR Generates Link
→
2. Share link with employee
→
3. Employee opens link
→
4. Frontend validates token
→
5. Employee fills form
→
6. Token marked used
🔒
Token Security: Each invite link expires in 7 days and can only be used once. The validate endpoint is public so the employee can check the token without logging in.
POST /api/onboardinginvite/generate ONBOARDING_INVITE_GENERATE Generate Invite Link

HR generates a unique, time-limited invite link for a new employee. Share this link with the employee via email or any channel.

Request Body

{
  "employeeEmail": "newemployee@example.com",
  "employeeName": "Anjali Singh"
}

Response 200

{
  "message": "Invite link generated successfully.",
  "shareableLink": "https://yourfrontend.com/
  nafa-barter-onboarding-invite.html
  ?token=abc123xyz",
  "token": "abc123xyz",
  "employeeName": "Anjali Singh",
  "employeeEmail": "newemployee@example.com",
  "expiresAt": "2026-03-24T10:00:00",
  "note": "This link expires in 7 days
  and can only be used once."
}
GET /api/onboardinginvite/validate/{token} PUBLIC — No Auth Required Validate Token

Called by the frontend when the employee opens the invite link. Validates the token before showing the onboarding form. No login required.

Response 200 — Valid Token

{
  "valid": true,
  "employeeName": "Anjali Singh",
  "employeeEmail": "newemployee@example.com",
  "expiresAt": "2026-03-24T10:00:00"
}

Response 400 — Invalid/Expired

{
  "message": "Token has expired."
}

OR

{
  "message": "Token has already been used."
}

OR

{
  "message": "Invalid token."
}
GET /api/onboardinginvite/all ONBOARDING_INVITE_VIEW All Generated Invites
